# Tractability pre-run checkpoint

Only the first checkpoint is authorized: budget enforcement, exact objective and exclusion tests, cost calibration, budget freeze and a pre-run commit. No nominal development or fresh confirmation may run before research-lead acceptance of that commit.

Primary SHGO and independent DIRECT search only observation-conditioned (r0,u_r), separately per inherited nuisance-depth branch. Reconstruction uses the accepted FIX2 bearing continuation and inherited physical bounds/cutoff. Exported scores must use the direct modal model. No old recovered state, pass/fail label, local width or oracle direction may enter search.

An external wrapper enforces the request budget before cache or forward evaluation. For limit N, requests 1 through N are admitted and counted, and attempt N+1 raises ObjectiveBudgetExceeded without incrementing the admitted-request counter. Blocked attempts are logged separately. Cache hits consume admitted requests. Exact forward calls and unique evaluated states are separate counters. This follows the explicit boundary rule in section 6 of the staged instruction.

Exception propagation is tested separately for both solvers. Exception chains and any callbacks after cap exhaustion are reported explicitly, without converting a failed propagation test into successful solver termination. If enforcement is incompatible, HARD_BUDGET_ENFORCEMENT_FAILED is recorded and no scientific runs or optimizer substitution are permitted.

R4 remains 0%. R3/A1/FIX1/FIX2 are frozen. A2, depth/B, SSP and P5 remain unopened.

## Exact observation-conditioned objective

The two optimizer coordinates are affinely normalized to [0,1]^2. They map to r0 in [45000,60000] m and u_r in [0.94,3] m/s. The inherited radial_profile reconstructs [r_km,theta_deg,v_mps,psi_deg] from those coordinates and the 121 observed bearings only. The reconstructed state must satisfy the inherited four physical bounds and the supplied bearing cutoff (numerical feasibility slack 1e-14 rad^2). There is no optimizer access to a historical case table, truth state, recovery flag, basin section, or Hessian direction.

Each of the 21 inherited depth labels is an independent nuisance branch. A direct_features call computes the three-frequency, 121-time relative-TL array using the direct modal model at the inherited effective-depth mapping (for example label 155 m maps to effective depth 154 m). The scalar acoustic score is the RMS of its residual against the supplied relative-TL observation. Infeasible coordinates receive a deterministic 1e6+bearing_cost penalty, J_exact=None, and no modal forward call; they never enter the exported feasible catalog. Repeated exact scores use a bitwise physical-state key plus depth label. No approximate coordinate rounding or interpolated score enters the cache.

n_unique_states_evaluated counts distinct prepared physical-state/depth keys, including feasibility-penalty states. n_exact_forward_evaluations counts direct_features invocations; each such invocation computes the whole three-frequency/time observation for one state and one depth. Cache hits consume objective requests but perform no modal call. Validation invocations are explicitly outside the optimizer request ledger and are reported separately. For cache-disabled cost calibration, repeated keys would still count each exact invocation while remaining one unique state.

## Native API behavior and candidate provenance

In the installed SciPy 1.15.3, SHGO propagates ObjectiveBudgetExceeded directly. DIRECT immediately leaves its native call with SystemError and preserves ObjectiveBudgetExceeded as __cause__. Both native classes and the full causal chain are retained in the evidence. Budget exhaustion is reported as HARD_BUDGET_EXCEEDED with solver_success=false; it is never reported as a normal successful optimizer result. An unrelated SystemError is re-raised. More than one refused callback or disappearance of the causal budget exception is an enforcement failure. No optimizer source patch, restart, polling loop, or optimizer substitution is used.

The cap can interrupt SHGO before a native minimum table is returned. The exported pre-run catalog therefore contains the feasible, exact-evaluated witnesses retained by the wrapper, explicitly labeled EVALUATED_WITNESS_NOT_CERTIFIED_LOCAL_MINIMUM. These witnesses are not a certificate of local stationarity or global coverage. They are sorted by direct J_exact and greedily deduplicated at [0.005 km,0.001 deg,0.005 m/s,0.05 deg] within a depth branch; a spatial index accelerates the same componentwise rule. Every saved witness is independently reconstructed from saved state coordinates and direct modal features. No development minima or recovered-basins conclusion is produced at this checkpoint. Any future driver must retain this provenance distinction when reporting minima/coverage.

## Calibration and frozen budgets

Calibration uses four fixed normalized coordinate pairs on all inherited depth branches (84 admitted requests). It supplies fixed exact synthetic bearings and an arbitrary zero relative-TL array. It reports request cost, feasibility and call accounting; there is no noisy observation, recovery flag, threshold test or development-panel read. The separate native hard-cap probes use an abstract quadratic callback with zero modal calls and caps [1,3,7,20,64,128]. Four physical compatibility probes use the same zero-TL fixture, two repeats per solver with cap 32, to verify repeatability and saved exact reconstruction. Synthetic truth-state self-match belongs only to the isolated unit test and is never an optimizer initialization.

The cost policy reserves an estimated six hours for the two complete 21-case, 21-depth raw-budget development families, including a factor of two for exact scoring plus verification. Let c95 be the measured 95th-percentile exact-request cost. The base request cap is min(128, the largest power of two <= 21600/(2*c95*21*21*2*(1+4+16))). A base below 16 stops as an infeasible declared cost policy. Each solver uses independent raw hard caps [base,4*base,16*base] per case and depth. The policy and all coordinate pairs are fixed before viewing any development recovery. The runtime estimate excludes I/O and catalog overhead and is not a wall-clock guarantee.

SHGO uses deterministic simplicial sampling; n is max(8,base/4) times [1,2,4], and iters=[1,2,3]. Internal maxev equals the corresponding cap and remains a soft option. Local optimization is SLSQP with maxiter=64, ftol=1e-12, eps=1e-8; minimize_every_iter=true and local_iter=1. DIRECT uses maxfun equal to the hard cap (soft), maxiter=1000, eps=1e-4, locally_biased=true, vol_tol=1e-16 and len_tol=1e-6. Neither solver uses a random seed. Every raw budget and depth branch starts with a fresh optimizer and exact cache. There is no transfer from lower budgets, the other solver, or previous recovered states.

The recovery threshold remains strictly J_exact<0.001 dB. State agreement remains [1e-5 km,0.001 deg,1e-4 m/s,0.01 deg], with identical inherited depth labels. Exact-alias diagnostic thresholds remain bearing RMS<1e-8 deg and acoustic RMS<1e-6 dB. The original scientific Gates and mandatory stops are preserved in A1_SEARCH_TRACTABILITY_AUDIT_DESIGN.md. They have not been evaluated in this pre-run checkpoint. In particular, no absence-of-alias conclusion is inferred from the synthetic compatibility catalog.

## Integrity and release boundary

FROZEN_INPUT_HASHES.csv snapshots all tracked R3/A1/FIX1/FIX2 scripts and numerical artifacts from the clean baseline checkout. Calibration, freeze and independent audit recheck every protected file. METHOD_FREEZE.json binds the new objective/controller, audit code, tests, full design, method, budgets, protected-input snapshot, byte-preservation attributes and raw API ledgers. The budget JSON also binds cost/API calibration summaries and environment. Git attributes preserve all frozen bytes across Windows checkout.

After manifest creation, all new tests run again, then the independent pre-run audit reconstructs all four counters from raw request ledgers, the budget rule from costs, geometry/bearing/exact scores from saved witnesses and ranking from reconstructed exact scores. These checks establish pre-run numerical integrity only. No final scientific Gate is assigned PASS. The checkpoint is committed and pushed before the first noisy development result, then execution stops for the research lead's audit.

Upon a later explicit release, the controlling design requires all SHGO development raw T1/T2/T3 runs before all DIRECT development raw T1/T2/T3 runs. Any failed raw-convergence or dual-solver Gate stops without fresh confirmation, T4, tolerance changes or repair-chain continuation. A fresh 16-case panel is generated only after both development Gates pass and after a separately frozen new seed/panel design. None of that is authorized or implemented as an enabled case driver here.
