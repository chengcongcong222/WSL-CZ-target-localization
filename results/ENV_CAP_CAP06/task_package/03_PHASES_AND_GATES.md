# CAP06 P0—P4阶段工作依赖与硬门

## 总体依赖

```
                         ┌── P1 O2垂向功率比 ───┐
P0单阵物理/接收合同 ────┤                      ├── P3 条件融合（仅合格配置） ── P4 资源反推+申请证据
                         └── P2 O6辅助方位 ────┘
```

P1/P2是相互独立的科学分支。P1失败不能阻断P2；P2失败不能改变P1的负/正结果。P3只接受各分支真正跨过接收与干扰剖面门的结果；没有P3资格时P4仍可以输出必要条件与失败边界。

|阶段|实际实验任务|证据最小目标|前置或停止|
|---|---|---|---|
|P0|历史来源/第一CZ身份、S0接收采集与估计合同、合成零控制，冻结新状态与资源|冻结不泄漏输入及正/反例|没有可信CZ背景不做CZ声学性能；仍可O6条件前端|
|P1|O2共源同步不同深度功率比、差分增益/噪声/AGC、可信前向判据|识别一个独立r/z导数方向或结构零反例|未经L3前向和L5提取，不运行真实CZ深度P95|
|P2|O6从假设性8元接收信号取得轴角，偏置、导航、关联和镜像候选|具可审计信号→轴角→多支→水平信息链|远场信号控制不算CZ前向；产品级条件可独立完成|
|P3|仅合格S0/S1/S2/S3，连续/外包络候选、多支、开发与留出|条件能力、失败及覆盖，或明确全体未准入|若无r/z提取，不发布5D误差|
|P4|有限资源Pareto、必要条件、稳健性、成本、研发精度等级、申请科研证据|正负结果和资源—信息条件链|无条件可行点也须报告完整STOP|

## 分支Gate

**P0-G0**：所有受保护历史Git文件身份、原始数据SHA、物理单位、发射/收深、阵元与噪声关联、被动未知源、S0/S1/S2/S3归属确认；解析常速/镜像/自由增益/弱场/零径向变化反例通过，Commit A冻结。

**P1-G1a功率定义**：确认同一源的同步多深度测量与平均算子的合法性；记录I类与CW功率物理差别；差分增益自由时有效信息零。

**P1-G1b声学前向**：若要认定为第一CZ传播量，需同一SCS/第一CZ身份下的独立可核查功率/相干场数值参考，接收深度、源谱、时间/频率积分、路径能量/噪声处理符合合同；出现未建证据则`O2_FIRST_CZ_FORWARD_NOT_ADMITTED`。可以以数学合成信号验证处理器，但是不得转为正式首CZ测深精度。

**P1-G1c非oracle提取**：算法仅得到模拟的有噪接收通道和合法校准元数据。报告正常、失锁、负功率扣噪、低能量、AGC缺失、差分增益漂移反例。验证导数/有效信息时同时剖面r、z、θ、v、ψ、环境和增益，不能只固定真源深。

**P2-G2a信号前端**：对至少合成单平面波正控制，方位处理器不见真角、真符号与真目标关联；报告空间波束或协方差提取、SNR、偏差及拒判。镜像双峰必须保存。

**P2-G2b产品级非oracle**：估计器使用前端输出而不是注入真实有向角；错支、漏检、假警、节点偏置/导航/关联、时间戳和共性误差全部进观测合同。不能把已有T3-W1的0.05°当新前端测出；旧T3作为独立条件参照。

**P2-G2c物理范围**：简化平面波单达波前端只准报告`ARRAY_FRONTEND_CONDITIONAL_NOT_CZ_MULTIPATH`；若没有经独立认证的首CZ全波前向，不报告首CZ波形级测向精度。

**P3-G3**：至少一条分支具有冻结的非oracle接收产物和独立验证；分层发布产品级条件4D vs 首CZ声学L6，多个场景全局候选正确分支保留与拒判/未决。若O2失败，S1/S3不能上报深度误差；若O6失败，禁止用有向真方位替换。

**P4-G4**：资源成本和有效信息证据一一对应，公平基线、误差预算、最坏场景与可信区间齐全。只在已测试配置集合中声称非支配；不从解析必要性推出已达到精度。

## STOP与继续政策

- 小型**开发阶段**可独立校正实现直至解析零控制及预算可接受；正式SCIENCE_STARTED/Commit A后冻结算法、参数和阈值，失败不追溯修补重跑。
- 不因无合作方数据而整体STOP；已有物理证据不够时停止对应**科学归因**，保留合成机制及另一路研究。
- 不因一个信号前端错误就让另一路没运行；但相同Gate的失败结果不能通过扩大种子、阵长、基线、SNR或换新算法“刷过”。
- 通用外部声学调用≤48，最大20,000新增MC配置；设计冻结每类的实际更低额度。科学累计壁钟≤72h，进程树RSS≤8GiB，新D盘≤30GiB，Git新增≤120MiB。超限先保存失败与状态，再STOP。
- 用户只在重大环境合同变化、未登记新硬件族、强需求改变、无法处理的科研真实性矛盾或超资源上限时需要介入；CP1/CP2可自动推送后继续。
